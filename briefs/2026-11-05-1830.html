OpenSSH 10.6p2: critical password authentication bypass on musl-based Linux such as Alpine

OpenSSH released 10.6p2 today to block a password authentication bypass in sshd that affects some Linux systems built and run without PAM; the project says the root cause sits outside sshd but is exploitable through it. Per The Hacker News, which rates it critical citing OpenSSH, a password between 257 and 1,024 bytes can log an attacker into accounts with no password, such as key-only accounts, on Alpine servers running the stock openssh-server package, as long as password logins are on and at least one other account has a password. Glibc systems, PAM setups and cloud-init images with PasswordAuthentication no are not affected. Alpine has fixed packages back to 3.16, and the reporter also names OpenWrt, Buildroot and Yocto. No exploitation reported yet. Takeaway: patch, or set PasswordAuthentication no on any musl-based box now.

DigiCert breach: archived customer data and some identity documents accessed

The certificate authority says a February 2025 server migration left an internal system, previously VPN-only, open to the internet with self-registration enabled, and an authorization flaw let outside accounts read archived customer data. An unauthorized account accessed names, business emails, phones and addresses between June 27 and July 2, 2026, and for some people driver's licences, passports or utility bills submitted for validation. DigiCert first spotted the accounts in June but only confirmed data access on October 19. It says certificate issuance, CertCentral and DigiCert ONE were not compromised. It has not said how many people are affected. Takeaway: if you validated certificates with DigiCert, expect targeted phishing using your real details.

CWPdoor: trojanized Control Web Panel web server plants a passive Linux backdoor

QiAnXin's XLab found a fake updater script that swaps the cwpsrv binary behind Control Web Panel (formerly CentOS Web Panel) for a backdoored build, restores timestamps and wipes shell history. The backdoor stays dormant until it gets an RSA-signed, AES-encrypted command in a custom HTTP header, enforces a five-minute replay window, and suppresses the request from access logs. XLab counts more than 340,000 exposed CWP instances and says a sample turned up on VirusTotal alongside the Ebury backdoor. How servers were first compromised is not stated in the report. Takeaway: CWP admins should verify cwpsrv hashes against a clean install and look for X-Ngx-Integrity headers in traffic.
