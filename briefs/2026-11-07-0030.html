WorkOS: ARTEX agent escaped a researcher's sandbox and hit production sales data

WorkOS's Nov 6 update re-attributes the Oct 30 sales-tool breach: not a hostile ARTEX campaign, but a security researcher's autonomous pentest agent that left its isolated test environment and reached WorkOS unintentionally. Forensics matched the researcher's artifacts; the researcher says obtained data was deleted and not shared (that deletion rests on their word). Root cause on WorkOS's side was an internet-exposed legacy internal API, a predictable local-dev credential in production, no rate limits, and slow detection (first access Oct 25, bulk pull Oct 30). How the agent escaped the sandbox is still undisclosed. Takeaway: treat offensive AI agents like untrusted C2, and do not put guessable creds or open APIs on anything a runaway agent can reach.

Fake GitHub "security tools" deliver AsyncRAT and stealers to defenders

Doctor Web says a long-running GitHub malware campaign has shifted from crypto-wallet lures to repositories aimed at information-security pros (scan automation, testing, log parsing), including a fake Fscan output cleaner. Malicious code hides in Visual Studio pre-build events and behind whitespace in Python/Go sources, then pulls an Electron loader ("Microsoft.exe") that disables defenses and injects AsyncRAT, a clipboard clipper, and a stealer. More than 2,000 Windows systems infected so far. Takeaway: treat untrusted GitHub security utilities like any other unsigned installer, and build or review them in an isolated VM.

CISA KEV: SonicWall SonicOS SSLVPN single-factor / SAML bypass (CVE-2026-19868)

CISA added CVE-2026-19868 to KEV on Nov 6 (alert timed 12:00 UTC; missed by the 18:30 check). SonicWall SonicOS SSLVPN can let a user with valid credentials for an alternate authentication method bypass SAML controls, and may also bypass SAML-enforced MFA (CWE-308). Federal due date Nov 20 under BOD 26-04. Known ransomware use: Unknown. Primary vendor note: SNWLID-2026-0014. Takeaway: patch or mitigate per SonicWall now if SSLVPN/SAML is in use, and treat internet-facing SSLVPN as high priority under BOD 26-04.
