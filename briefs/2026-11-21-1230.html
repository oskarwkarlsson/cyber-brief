Critical GPGME double free: update mail and crypto apps

GnuPG's advisory (Nov 20, 19:01 CET) says an OpenPGP key with a crafted very long user ID triggers a double free in GPGME, the library most mail clients, many XMPP clients, Samba, Flatpak and Gpg4win use to talk to gpg. It can be used to exfiltrate data from apps, for example by sending signed data, and RCE "can't be ruled out". CVE-2026-129975 affects every version before 2.3.0, including statically linked copies. Fix: GPGME 2.3.1 (legacy 1.24.4), Gpg4win 5.1.2, Debian DSA-6646-1 and DLA-4924-1; no workaround. Disclosure was pulled forward from Nov 25 because of Ruby2Shell. No exploitation reported.

Cairn's zero-day named: MONAI Label CVE-2026-133968, no release yet

Update to Amazon's Cairn report: the flaw the China-linked operator's AI agents found is a path traversal in MONAI Label (open-source medical imaging labelling server) via PUT /datastore/image, now CVE-2026-133968 at CVSS 9.8, with NVD noting exploitation in the wild since September 2026. Version 0.8.5 and earlier are affected, auth is off by default, and the fix is merged in source (PR 1915) but there is no fixed release. Until then: firewall it off, enable auth, run it unprivileged, and check for unexpected Python startup files.
