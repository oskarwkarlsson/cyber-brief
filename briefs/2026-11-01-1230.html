A CVSS 10 flaw in Canonical's LXD and MicroCloud lets anyone who can reach the API log in as a trusted client using only that client's public certificate

Vulns

LXD and MicroCloud auth bypass (CVE-2026-112816, CVSS 10.0): impersonate any trusted client, possibly up to root on the host

LXD's mutual TLS check compared every certificate a client sent against the trust store, not just the leaf, so an attacker can slip a trusted client's public certificate in as an intermediate and be accepted as that client. In MicroCloud, an attacker can intercept a joining member's public certificate and then act as that member. Canonical says this can give full access to the cluster and its VMs, and root on the host depending on the victim's privileges. Affected: LXD 4.0.14, 5.0.10, 5.21.8 and 6.9 lines; fixed in 4.0.15, 5.0.11, 5.21.9 and 6.10.1 (snaps released Oct 29) and MicroCloud 2.1.5. The bug was referred by the Incus project. No exploitation reported. If your LXD HTTPS API is reachable from outside, update or firewall it now.
