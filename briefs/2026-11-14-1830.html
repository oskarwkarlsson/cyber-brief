Cursor breach traced to a Fireworks-exposed key; agent traces with unredacted credentials opened the door to internal SaaS data

In a 13 November update, Cursor says an attacker used an access key it had issued to Fireworks AI (exposed by Fireworks) to copy a read-only bucket of coding-agent traces, mostly from 2025 and only from sessions not in Privacy Mode. Some traces held unredacted credentials (under 0.01% of customers had API credentials exposed), which the attacker used to reach Cursor SaaS tools and take archived non-production source repos, limited support data and emails, usage metrics and contact details, summaries of some agent conversations, and credentials users had sent to Cursor support. A stolen credential then let them plant the malicious Anthropic.claude-code 2.1.312/2.1.313 builds in the marketplace cache on 29 October (up to 5,000 users, about 11 hours). Cursor says production, customer code repos, official app releases and signing keys were not affected, last attacker activity was blocked on 1 November, and it has moved all inference off Fireworks. Takeaway: if your team uses Cursor, check for its direct notice and rotate any keys it lists; never paste secrets into agent sessions or support tickets.
