Vulns

Apache HTTP Server 2.4.71 fixes a critical, unauthenticated mod_http2 code execution bug

CVE-2026-119618 is a race condition in mod_http2's assign_headers() that can corrupt the heap and lead to remote code execution, affecting 2.4.55 through 2.4.70 (and mod_h2 2.0.8 to 2.0.42) where HTTP/2 is enabled. Apache rates it critical and credits Anthropic's OSS scanner and Google Cloud Vulnerability Research, who found it independently. Wiz says no exploit is public and there are no reports of exploitation, but 64% of the cloud environments it sees have vulnerable resources and 51% have exposed ones (not adjusted for configuration). The Hacker News cites CVSS 9.8 and says some Linux distributions are still waiting on packages. The same release fixes a mod_md crash (CVE-2026-106023). Takeaway: upgrade to 2.4.71 or disable HTTP/2 (Protocols http/1.1) on internet-facing servers until your distro ships it.

ScreenConnect MSP campaign: abused third-party extensions and a worm-like SCKit toolkit, 288 endpoints in 48 organisations

Huntress now counts at least 288 managed endpoints across 48 organisations, with activity first seen at 18:47 CET Wednesday. Attackers use access to cloud-hosted ScreenConnect panels to push Run commands that install rogue ScreenConnect clients delivering SCKit, which adds Defender exclusions, replaces the legitimate install with an attacker copy, creates a scheduled task named TrapWatch and sets a relay trap for session cookies, so a technician who connects to an infected device can be compromised in turn. Huntress says at least one script looks LLM-written. ConnectWise says there is no sign of a ScreenConnect vulnerability or a breach of its own infrastructure; its initial view is abuse of independent third-party extensions, and it has disabled five of them across about 400 partner environments. Initial access is still unknown. Takeaway: check your instance for those extensions, review Run Command history, and only open sessions to suspect machines from an isolated workstation.

Maersk confirms data was taken from a legacy LF Logistics system as WhiteArmor demands $5 million

A.P. Moller-Maersk says attackers accessed and extracted data from a local legacy system from a previous acquisition, that findings so far strongly suggest no sensitive data was disclosed, and that bookings and API/EDI integrations are unaffected. WhiteArmor claims about 100 GB from the LF Logistics platform (acquired 2022), including driver profiles with plaintext passwords and admin accounts, and wants $5M in bitcoin (claim, unverified; Maersk has not named the group). Takeaway: Maersk and LF Logistics partners in Asia should expect themed phishing and rotate any shared credentials.

AI/Cloud

AI pentest agents are now a standard intrusion tool: AntiFox hits AWS secrets as Unit 42 counts 1,900+ exposed ARTEX-style consoles

Arctic Wolf links AntiFox, an open-source agentic pentest framework derived from ARTEX, to intrusions that web-shelled IIS apps, harvested web.config secrets and then fired hundreds of AWS API calls in about 30 minutes, with one successful GetSecretValue on a production secret (per BleepingComputer). Unit 42 separately says its incident responders handled multiple intrusions from servers hosting ARTEX consoles and tracked a coordinated ARTEX campaign against cloud environments; it counted 609 internet-facing ARTEX hosts and 1,323 running CyberStrikeAI as of October, and notes ARTEX has gone closed-source while forks fill the gap. Takeaway: alert on bursts of AccessDenied followed by secrets or S3 access from new ASNs, and treat leaked cloud keys as exploited within minutes.
