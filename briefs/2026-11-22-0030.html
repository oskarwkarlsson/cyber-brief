Entra Connect Health API flaw exploited, tenant metadata exposed

In a notice to admins (via Azure Service Health), Microsoft says a bug introduced in the Connect Health API on July 23 and found on Nov 9 was exploited for unauthorized read-only access to tenant-level metadata: technical-contact and admin email addresses, tenant IDs, names and initial domains, license tiers, sync status, and an expired, decommissioned agent-registration certificate. Microsoft says no passwords, hashes, tokens, valid keys or Azure subscription data were exposed and no configuration changes were found. Server-side fix on Nov 19; no customer action required. The attacker, tenant count and start date are not disclosed; MSPs report notices for several tenants. Expect targeted phishing at exposed admin addresses: enforce phishing-resistant MFA for privileged accounts and review Entra sign-in and audit logs.

Rackspace Spot breach exposes customer Kubernetes Secrets

According to a customer notice seen by BleepingComputer, an intruder used leaked credentials on Nov 17 (about 01:20 to 23:00 CET) to act as legitimate users in some customer organizations on Rackspace Spot, the managed Kubernetes platform built with Platform9: creating pods, reading any Secret in affected clusters, listing nodes and volumes, and possibly grabbing Spot API and refresh tokens. Rackspace learned of it from a customer on Nov 18, revoked tokens, removed pods and rotated keys; the console was down until Nov 21. Customers should reissue Spot tokens, pull fresh kubeconfigs, rotate every credential stored as a Secret and check downstream logs (databases, registries, Git, storage) back to Nov 17. IOCs: 23.224.79.106, range 23.224.0.0/15, pod prefixes i1, glm-, probe. Number of customers affected not disclosed.
