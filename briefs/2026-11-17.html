Vectors

Optimizely Web supply-chain attack: malicious Project JS on 178 organisations incl. Zoom, BBC, CNN, HSBC, GitLab

Scott Helme (Report URI) found an attacker had added a loader for 1688360.cc/track.js to the "Project JavaScript" of customer snippets served from cdn.optimizely.com, so it ran with each site's privileges. The kit swapped crypto addresses, skimmed cards, stole cookies and screenshots, and routed iPhones to the Coruna and DarkSword exploit kits; crypto has been stolen. Infected snippets fell from 169 of 188 at 21:56 CET to 1 at 22:52 CET Monday. How the attacker got write access is unknown and Optimizely had not commented. Takeaway: Optimizely Web users check Project JS, purge CDN caches and rotate tokens; consider CSP on third-party marketing scripts.

Infoblox confirms hackers accessed company information via a compromised data migration vendor

The DNS, DHCP and identity security firm told TechCrunch it is investigating "unauthorized access to certain company information through a compromised third-party data migration vendor" and has called in outside responders. Two sources say the vendor did SharePoint migration work and one says sensitive customer data was taken; Infoblox has not confirmed customer impact or scope. Takeaway: Infoblox customers should watch for notification and targeted phishing, and everyone should review what migration vendors still hold access to.

N-central 2026.4 Hotfix 3: 17 more CVEs, legacy API removed, agents and probes must be upgraded

N-able released HF3 (build 2026.4.1.39) on Monday as a critical security update fixing CVE-2026-129271 to -129287, incl. an MMS3 appliance auth bypass via predictable passcode, root command execution through audit-export syslog injection, several missing-authentication endpoints, XXE and a path traversal to RCE. The legacy API option is gone for good, which closes the 4EverAble2Shell path that attackers have been exploiting to drop crypto miners, incl. on HF2. Remote control and Intune integration remain blocked. Hosted servers are patched automatically; on-prem must upgrade now, and all agents and probes must be updated or they can be impersonated.

AI/Cloud

Barracuda breached by an ARTEX-driven intrusion: about 10 cloud accounts in about 44 hours

Barracuda says an attacker used an exposed valid cloud access key on 1 to 2 November, then reused secrets it found to move through secret stores, configs, Kubernetes service accounts and metadata services, hunted crypto wallets, and left a Kubernetes backdoor. It says the tradecraft matches ARTEX but has not attributed it. Same day, Google GTIG reported agents turning patches into n-day exploits. Takeaway: kill long-lived cloud keys and audit clusters for unknown workloads.
