"wfx" campaign: stolen GitHub tokens push a CI secret stealer into thousands of repositories, then erase the traces

Aikido Security first reported it; SafeDep counts 8,093 public repositories that received malicious commits between 13:46 CET Tue 10 Nov and 05:36 CET today, with the campaign still active. The attacker first opens a "docs: dependency audit notes" pull request from a wfx-docs branch to test write access (about 61,800 such PRs from roughly 4,830 accounts, 91% still open), then injects the stealer into an existing workflow (7,309 repos), a new workflow, or an npm postinstall hook (771 repos, which also runs on developer machines). Aikido says the stealer ran in at least 1,806 repos. It sends all secrets, variables and an OIDC token out over HTTP or Telegram, tries to plant AWS and Azure backdoors that survive rotation, and the commit is usually reverted within minutes with run logs deleted. Malicious versions also shipped in Packagist (digitalelvis/neuronai-studio 3.14.3) and two Go modules. How the tokens were stolen is not known. Takeaway: search every repo you can write to for wfx-docs branches or PRs from Tuesday on; if hit, revoke the author's tokens, SSH keys and OAuth grants, rotate every secret the repo can read, and check cloud accounts for new identities.

N-central again: "4EverAble2Shell" and "Agent2Shell" work against the 10 November hotfix, and probes started within hours

Researcher Sean Bales, who disclosed Able2Shell, published new proof-of-concept exploits that he says work on N-central 2026.4 HF2 (build 2026.4.1.26): unauthenticated root code execution on the server, and SYSTEM command execution on managed Windows agents if the appliance ID is known. N-able says the server issue needs the non-default Legacy API turned on and exposed to the internet, hosted N-central is not affected, and it is investigating. watchTowr says it is already seeing 4EverAble2Shell probes; Presidian told The Hacker News it saw attempts chaining Apache Axis CVE-2026-90436 with it, with no confirmed compromise so far. Takeaway: on-prem N-central owners should disable the Legacy API now and watch for compromise; MSP customers should ask their provider.

Red Hat Quay CVE-2026-123710 (CVSS 9.8) lets attackers install their own registry signing key

Red Hat says the flaw in Quay's service key server lets an unauthenticated attacker take over registry token signing when anonymous access is on, and any valid account can exploit it when it is off. With a rogue key the attacker can mint tokens for read and write on every repository: steal private images and their embedded secrets, or overwrite images others pull. The rogue key can be set never to expire, survives restarts and password or robot token resets. No fixed release is named yet; fixes were merged on GitHub on 11 Nov. Not reported as exploited. Takeaway: if you run self-managed Quay, restrict access to the key service, audit for unexpected service keys, and patch when a release lands.

MongoDB CVE-2026-118383 (CVSS 9.5): two pre-auth pings can set up a crash of a replica set member at failover

Datadog Security Labs reproduced the use-after-free on 8.0.34. Vulnerable servers accept ping before login, so enabling authentication does not stop it; the crash only fires if the poisoned member later wins an election while lagging, which the attacker cannot see or force. Shard and config server members are affected, standalone mongod is not. MongoDB found it itself, says it knows of no exploitation, and Atlas clusters get fixes in maintenance. Datadog notes a public PoC claims end-of-life 8.2.12 is still affected. Takeaway: a denial-of-service risk, not data theft; upgrade every self-managed replica set member and keep MongoDB off untrusted networks.
