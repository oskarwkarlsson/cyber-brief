Chrome 157 fixes CVE-2026-125350, a use-after-free in XML that Google says is exploited in the wild

Google's Stable channel update on Monday (157.0.8103.50/.51 for Windows and Mac, 157.0.8103.50 for Linux) carries nine security fixes, and Google says it "is aware that an exploit for CVE-2026-125350 exists in the wild". The bug, a high-severity use-after-free in XML, was reported anonymously on 6 November, so the fix shipped within three days; details are restricted. A second XML use-after-free (CVE-2026-125346) and a V8 type confusion (CVE-2026-125344) are in the same release. Extended Stable 156.0.8078.96 also carries the fix, and HKCERT rated the bundle "Extremely High Risk" today. It is not on CISA KEV yet. Takeaway: force a Chrome restart across the fleet to land 157.0.8103.50 or later, and watch Edge, Brave and other Chromium browsers for matching builds.

Ethersphere's own release automation pushed malicious bee-js 13.3.0 and Swarm Desktop 0.56.2

Attackers used two compromised GitHub accounts, the bee-worker release bot and a long-time maintainer, to publish a trojanized @ethersphere/bee-js 13.3.0 to npm (live about 75 minutes on Monday from 00:09 UTC, with valid provenance because the real workflow built it) and a signed, Apple-notarized Swarm Desktop 0.56.2 that the app's auto-updater offered to Windows x64 and Apple Silicon users for about eight and a half hours. Both carry a loader that pulls code from api.frameworkmetrics[.]xyz, steals the Swarm node's wallet key plus the plain-text password in config.yaml, and installs a backdoor: a Go shell that reads its C2 address from an Ethereum contract on Linux and macOS, and a real ScreenConnect client on Windows. Socket ties it to the SleepyDuck / EtherDuck Open VSX campaign via the same contract. Download counts look small (about 10 for bee-js, 65 for 0.56.2 including researchers), and no fund theft was reported. Takeaway: search lockfiles and CI logs for bee-js 13.3.0, pin 13.2.0, move Swarm Desktop to 0.56.3, and treat any machine that ran either as fully compromised; for your own projects, gate signing and publish workflows behind approvals, since provenance proves where code was built, not that anyone reviewed it.

N-able N-central still offline: 33 Able2Shell zero-days public, no hotfix, no CVEs (recap of the 00:30 alert)

After an independent researcher dumped details and proof-of-concept code for 33 alleged N-central flaws on GitHub on Sunday night, N-able took its hosted N-central environments offline in the Americas, Europe and Asia-Pacific on Monday and told on-premises customers to shut down their servers until further notice. Huntress and others count at least four exploit chains, three to remote code execution and one to root, several without authentication. As of this morning N-able says it is still developing and validating a hotfix, has seen no active exploitation or unauthorized data access, gives no restore date and promises updates every four hours; no CVEs have been assigned. Takeaway: RMM servers push code to every managed client, so keep on-prem N-central off, preserve logs before rebuilding, review admin logins and script deployments since 8 November, and ask any MSP you rely on whether it runs N-central.

Four CISA KEV adds due Thursday 12 November: SSHole, GPUStack, FreeSWITCH and IBM Aspera Faspex (recap)

CISA added four exploited bugs on Monday with an unusually short three-day deadline: OpenSSH CVE-2026-123158 (SSHole, an authentication bypass on Linux that BleepingComputer, SecurityWeek and Ars report is being used to run commands, steal credentials and persist, so far mostly by botnets and crypto miners), GPUStack CVE-2026-102895 (unauthenticated admin on AI model clusters), FreeSWITCH CVE-2026-116779 (SIP MESSAGE command injection, fixed in 1.11.3) and IBM Aspera Faspex CVE-2026-123218 (incorrect authorization). The catalog was last released at 19:54 UTC Monday. Takeaway: patch internet-facing OpenSSH first, then Faspex file-transfer servers, which extortion crews have favored before; anyone on the federal clock has until Thursday.
