Java4Shell turns urgent: CISA tells everyone to patch the OpenJDK Base64 bug now, Microsoft's agent-framework package on PyPI is hijacked to steal Azure and CI credentials, and Norway's Equinor fights an ongoing cyberattack on its IT systems

Vulns

Java4Shell (CVE-2026-114938): CISA urges immediate patching as details and a crash PoC go public

Calif disclosed a memory-corruption bug in OpenJDK's AVX-512 accelerated Base64 decoder (OpenJDK 17.0.6 and later, incl. Oracle, Corretto, Temurin, Microsoft, Zulu and Red Hat builds) and says it reached unauthenticated RCE on default Keycloak, Jira, Confluence, Artifactory, Jenkins and PingFederate. It needs an x86-64 CPU with AVX-512 VBMI and an app path that feeds attacker Base64 to the decoder. Oracle fixed it in its 17 November update (rated 8.1; Calif says 9.2). CISA issued an alert telling organisations to patch immediately, check bundled runtimes in containers and appliances, and watch for unexpected JVM crashes; JPCERT published a CyberNewsFlash overnight. Only a crash PoC is public and no exploitation is reported. Takeaway: patch internet-facing Java apps first; stopgap -XX:-UseBASE64Intrinsics.

Microsoft's agent-framework on PyPI hijacked: versions 1.26.1 and 1.26.2 steal Azure, DevOps and GitHub Actions credentials

Wiz says a malicious 1.26.1 of Microsoft's Agent Framework Python package (about 41,000 downloads a week) was uploaded at 21:35 CET on 17 November, and a repacked 1.26.2 followed at 22:08 after the first was pulled; both were gone by 22:30. A .pth file runs the stealer on every Python start, even if the package is never imported. It grabs secret-looking env vars, other processes' environments, Azure CLI, npm, pip, git, Docker and Hugging Face credentials, Azure managed-identity and DevOps OIDC tokens, and in 1.26.2 GitHub Actions OIDC tokens, posting them to a free webhook.site URL that captured at most 50 requests. Root cause is unconfirmed: there is no matching release tag, so it looks like a direct upload. Takeaway: pin 1.26.0, hunt for agent_framework_meta.pth or af_runtime_diag.pth, rotate every secret those hosts and runners held.

Incidents

Equinor detects an ongoing cyberattack on some IT systems; production unaffected

Norway's Equinor, Europe's largest gas supplier, said at 18:55 CET on 17 November that it is fighting an ongoing attack on certain IT systems, with no sign of data theft and no impact on operations or production. Reuters reports internal email was down; NTB says internal applications are disrupted. Norway's NSM is assisting and says the incident confirms its high risk assessment (it raised the national cyber risk level to four of five last month); PST is also informed. No attribution, attack type or start time has been given. Takeaway: Nordic energy suppliers and Equinor partners should expect lookalike phishing and check any trust links into Equinor systems.

Optimizely confirms the CDN malware came from a flaw in its own Web Experimentation platform

Optimizely now says an unauthorised party exploited a vulnerability in Experimentation to add malicious JavaScript to some customer projects; the flaw is fixed and injected code removed, but it has given no root cause or customer count. Report URI counted 188 infected scripts across 178 organisations incl. CNN, BBC, Zoom and HSBC, serving card skimmers, crypto clippers and iOS exploit kits from 13 to 16 November. Mandiant and Unit 42 (calling it OPTIMJACK) published defender guidance, stressing cleanup stops delivery but not prior exposure. Takeaway: any Web Experimentation customer could have been exposed; audit Project JS and change logs and rotate tokens.
