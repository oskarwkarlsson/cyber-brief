SAP hit via GitHub ("Project Granite")

SAP confirmed suspicious activity and said it has found no evidence of access to customer business data. Per Der Spiegel (internal memo, insider sources) attackers stole employee authentication tokens and used them to copy and modify source code on SAP's GitHub, possibly with AI help. Handelsblatt reports SAP replaced signing keys, limited GitHub access and suspended automated development operations. No report says tampered code reached customers, and it is unclear whether proprietary code was touched. Details beyond SAP's statement rest on anonymous sources. Takeaway: watch for SAP guidance on its GitHub-hosted tools and samples; it is the third dev-token-to-repo breach this week after 1Password and Todoist.

Vulns

NFS2ROOT: remote root in Linux nfsd

CVE-2026-99362, a heap overflow in the Linux kernel NFS server present since 3.16 (2014), lets an unauthenticated attacker who can reach TCP 2049 corrupt kernel memory, bypass KASLR and run a command as root. Found by ANSSI's Jérémy Jean; OpenSec built a full remote-root exploit. Affects kernels older than 6.12.117, 6.18.61 and 7.3.2 with nfsd v4.1/4.2 running. No exploitation reported yet. Takeaway: patch and reboot file servers, NAS and Kubernetes storage nodes, or restrict port 2049 to trusted clients.

Cacti zero-day, public PoC, no patch

Researcher ek0ms savi0r published "4HTTP2SHELL/4HTTP2ROOT": four unauthenticated requests to Cacti Core 1.2.31 (latest) with the guest account enabled store SQL in a profile setting, rewrite a poller command and run it via popen(). watchTowr's FAQ lists the patch as pending and no CVE; no in-the-wild exploitation reported. Guest is off by default, which limits exposure. Takeaway: disable the guest account, keep Cacti off the internet and check poller_item entries for odd commands; Cacti holds credentials for network gear.

Official Q-Dir and DesktopOK downloads trojanized

AhnLab ASEC found that installers for Q-Dir 12.83 to 12.85 and DesktopOK 12.82 and 12.85 from the official SoftwareOK site, and from the apps' own update process, were swapped for wrappers that run the genuine signed app while pulling a Python RAT (shell, file transfer, screenshots, security-product inventory) from mail.c1a2[.]top, with C2 at 8.210.69[.]51:9876 and a scheduled task posing as Edge. How the files were replaced and the exposure window are unknown; no actor named. Takeaway: check hashes and look for \UPnp\MicrosoftEdge_dcntel tasks; reinstalling does not remove the RAT.
